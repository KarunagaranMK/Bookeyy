# Bookey

Bookey is an interactive, narrated learning book. A learner picks a course and
answers a short survey. Then they read pages while a tutor narrates, draws
diagrams, highlights terms, runs code and answers scoped questions.

**This repository is a frontend-only demo.** Every realtime and data feature runs
on seeded mock data and a deterministic mock client. No real API, database, paid
AI service or secret is needed to run it. See [`BACKEND_HANDOFF.md`](./BACKEND_HANDOFF.md)
for the integration plan.

## Prerequisites

- Node.js 20.9+ (Next.js 16 requirement)
- pnpm 9+ (`corepack enable` will provide it)

## Install and run

```bash
pnpm install
pnpm dev          # http://localhost:3000
pnpm build        # production build, includes the TypeScript check
pnpm start        # serve the production build
pnpm exec tsc --noEmit -p tsconfig.json   # type check only
```

`next.config.mjs` does **not** ignore build type errors. A type error fails `pnpm build`.

The `iqrabook/` folder is a legacy prototype (separate frontend plus a Python
backend). It is excluded from `tsconfig.json` and isn't part of the Next.js app.

## Design and theme rules

- Colors come only from the semantic tokens in `app/globals.css` (`background`,
  `foreground`, `primary`, `muted`, `card`, `border`, `book-*`, …). Don't
  hard-code hex values in components.
- Light and dark themes come from `next-themes`. Every new surface must be
  checked in both.
- Two font families: the display face for headings (`font-display`) and the
  sans face for body text. Both are configured in `app/layout.tsx`.
- Use shadcn primitives from `components/ui/` and Bookey wrappers from
  `components/ui-kit/` (buttons, empty states, progress ring, …) before building new ones.
- Motion uses `framer-motion`/GSAP with the shared easings in `lib/motion.ts`
  and must respect `prefers-reduced-motion`.
- Layouts are mobile-first. Use flex/grid with Tailwind scale spacing.

## Mock-only features

Everything below works in the browser with no backend:

| Feature | Implementation |
| --- | --- |
| Narration (start/pause/resume/seek/speed/restart) | `MockBookClient` streams timed `text_chunk` frames from seeded page scripts. **No audio is played.** `lib/narration/audio-player.ts` is a no-op seam for future TTS |
| Diagram drawing, highlights, cues | Computed from seeded page data and the active word index |
| Code runner | `lib/runner.ts`: a deterministic demo runner that only knows the seeded Python examples |
| Tutor Q&A | Demo answers, sources and scope refusals generated by the mock client |
| Survey | Saved to `localStorage`. Changes reader defaults and illustrations |
| Auth | Forms only. No sessions |
| Bookmarks, notes, history, recent searches, preferences, notification read state, profile | `localStorage` under the `bookey:v1:` namespace (`lib/storage.ts`) |
| Admin courses, members, knowledge base, tutor settings | Local demo state. Toasts say “demo” / “simulated” |
| Course, page, progress, badge data | Seed files in `lib/mock/` |

Clear all demo data from **Settings** (removes only `bookey:v1:*` keys) or with
**Reset demo data** in the admin profile menu.

## Environment variables

The demo needs **no** environment variables. Names that exist or are reserved:

| Name | Status |
| --- | --- |
| `NEXT_PUBLIC_BOOKEY_WS_URL` | Reserved. Future WebSocket endpoint for the book client |
| `NEXT_PUBLIC_BOOKEY_API_URL` | Reserved. Future REST base URL for FastAPI |
| `NEXT_PUBLIC_DEV_SUPABASE_REDIRECT_URL` | Present in the Vercel project. Unused by the current code |

Never put secrets in `NEXT_PUBLIC_*` variables. They ship to the browser.

## Known limitations

- Only **Python chapter 1, “Variables” (6 pages)** has full reader content.
  Other pages fall back to a seeded placeholder lesson.
- The code runner only executes the seeded examples. Other code returns an
  “unsupported in demo” result, never a fake success.
- Narration is silent and text-timed. Admin voice previews say they're
  unavailable until text-to-speech is connected.
- `web-development` is shown as unavailable on purpose.
- All persistence is per browser. Nothing syncs across devices.
- `lib/mock/learning.ts` is the single course seed used by the learner app,
  marketing pages and admin.

## Testing checklist

- [ ] `pnpm build` completes with no type errors.
- [ ] Every route in the map renders. Unknown ids show not-found UI.
- [ ] Header/footer navigation, mobile menu and all CTAs reach their target.
- [ ] `/courses`: search, filters, sort and the empty-results state work.
- [ ] Survey: finish it, reload, and confirm the answers persisted and changed reader defaults.
- [ ] Reader: toggle full/guided mode. Start → pause → resume → restart narration.
      Confirm diagrams draw, terms highlight and the code panel opens on cue.
      Change page mid-narration and confirm the state resets.
- [ ] Code lab: run the seeded example, then an edited/unsupported program.
- [ ] Tutor: ask an in-scope and an out-of-scope question.
- [ ] Bookmark, write a note, search, mark a notification read, reload: all of it persists.
- [ ] Admin: create/edit/publish a course, add a KB file, invite/remove a member.
      Toasts must read as demo/simulated.
- [ ] Check light and dark themes, and mobile width (375px).
