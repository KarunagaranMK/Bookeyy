## STT Chain

```
audio_in event (webm/opus, base64)
    │
    ├─ Size check: > 10 MB → reject with error
    ├─ Duration estimate: > 60s → reject
    │
    ├─ GroqWhisperSTT   (GROQ_API_KEY set)
    │   └─ POST /openai/v1/audio/transcriptions → verbose_json
    │       → language, duration, transcript
    │
    └─ FasterWhisperSTT  (fallback, local CPU)
        └─ lazy-load model (large-v3-turbo, int8)
        └─ asyncio.to_thread (non-blocking)
            → transcript, language, duration
    │
    ▼
question_received event {question, source: "voice", sessionId}
    │
    └─ feeds into B4 tutor pipeline
```

## TTS Chain

```
synthesize_segment(text, voice, speed)
    │
    ├─ normalize_for_tts(text)         ← always first
    ├─ cache_get(text, voice, speed)   ← hash key: sha256(text+voice+speed)[:24]
    │   └─ HIT → return cached audio + timings (from_cache=True)
    │
    ├─ EdgeTTSProvider                 (ta-IN-ValluvarNeural / PallaviNeural)
    │   └─ stream() → audio chunks + WordBoundary events
    │       → native per-word timings (100ns precision)
    │       → fallback: estimate_word_timings() if no boundaries
    │
    └─ SilentTTS                       (final fallback)
        └─ audio_bytes = b""
        └─ estimated word timings (150 wpm weighted)
        └─ notice shown to learner
    │
    ├─ cache_set(text, voice, speed, audio, timings, mime)
    └─ return TTSResult
```

## Text Normalizer (Tanglish → TTS)

The normalizer transforms Tanglish text (Latin script) so TTS produces natural speech:

| Transform | Input | Output |
|---|---|---|
| Code fences | ` ```python\n...``` ` | `" code block "` |
| URLs | `https://python.org` | `"URL"` |
| **Snake_case before markdown strip** | `my_list` | `"my list"` |
| Markdown (backticks, asterisks) | `**bold** and \`code\`` | `"bold and code"` |
| Operators | `x != y` | `"x  not equal  y"` |
| Numbers | `42`, `3.14` | `"forty two"`, `"three point one four"` |
| Currency | `$10` | `"ten dollars"` |
| Known acronyms | `API`, `URL` | kept as-is |
| Unknown acronyms | `CNN` | `"C N N"` (spelled out) |

> ⚠️ **Critical fix**: Snake_case expansion is applied **before** markdown stripping so that `_` in identifiers is correctly expanded rather than stripped.

## Word Timing Sync

Every `audio_chunk` event carries `wordTimings`:

```json
{
  "type": "audio_chunk",
  "seq": 0,
  "data": "<base64>",
  "mime": "audio/mpeg",
  "final": false,
  "wordTimings": [
    {"word": "Python", "startMs": 0, "endMs": 320},
    {"word": "la",     "startMs": 320, "endMs": 420},
    ...
  ]
}
```

**`startMs` is strictly monotonically non-decreasing** (guaranteed by construction):
- edge-tts provides native WordBoundary offsets in 100ns units → converted to ms
- Fallback: `estimate_word_timings()` distributes duration proportional to character count + punctuation weight

Cues (from B3 `GeneratedPage`) use the same clock: `atWord` triggers the cue action when that word's `startMs` is reached.

## Audio Cache

```
Cache key: sha256(normalized_text + voice + f"{speed:.3f}")[:24]
Storage:   {AUDIO_CACHE_DIR}/{key}.audio  (raw bytes)
           {AUDIO_CACHE_DIR}/{key}.json   (timings + mime)
```

- Cache entries never expire (audio for given text+voice is deterministic)
- Hit/miss counters exposed via `cache_stats()`
- Best-effort writes (errors silently logged, never fail the request)

## Pre-synthesis for Pages

After B3 generates a page, call:

```python
from app.voice.pipeline import synthesize_segment
from app.page_gen.schema import GeneratedPage

async def pre_synthesize_page(page: GeneratedPage, voice: str, speed: float):
    for seg in page.segments:
        if seg.narration or seg.text:
            result = await synthesize_segment(seg.narration or seg.text, voice, speed)
            # Result is now cached — next request for same text is instant
```

## Interruptions

When a learner asks a question mid-narration (matching B4 queue design):
1. `audio_in` frames arrive → STT runs
2. Transcript emitted as `question_received {source: "voice"}`
3. B4 queue.enqueue() called
4. Current narration sentence completes
5. Queue is drained in FIFO order → tutor answers

The frontend plays the current sentence to completion before cutting — no abrupt audio stops.

---

## Pause / Resume / Seek / Speed

| Action | Backend behaviour |
|---|---|
| `pause` | Narration task suspended; audio buffer continues draining client-side |
| `resume` | Narration resumes from current position |
| `seek` | Jump to sentence index; pre-synthesized audio available from cache |
| `speed` | `speed` param passed to `synthesize_segment`; cue timings scaled proportionally |

Speed change preserves cue order: cues fire by word position, not absolute time.
