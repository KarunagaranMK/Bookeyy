## Features Implemented

### 1. Upload endpoint — `POST /api/admin/documents/upload`
- **Admin-only** (403 for learners)
- **Magic-byte verification** — extension alone never trusted:
  - PDF: `%PDF` header
  - DOCX: `PK\x03\x04` ZIP magic (OOXML)
  - MD/TXT: UTF-8 printable heuristic + extension cross-check
- **25 MB hard limit** — enforced before touching storage (413)
- **Random storage key** — `documents/{course_id}/{16-hex-rand}.{ext}` — original filename never exposed in storage
- **Per-course association** — validated against courses table
- **Background processing** — `BackgroundTasks.add_task(process_document, doc.id)` — request returns immediately with `status="uploaded"`

### 2. Status lifecycle
```
uploaded → processing → indexed
                     ↘ failed  (retryable via POST /retry)
```
SSE stream at `GET /api/admin/documents/status-stream` pushes status changes every 2 s.

### 3. Parsing
| Format | Library | Headings | Page Numbers |
|--------|---------|----------|-------------|
| PDF | pymupdf (bold/large font heuristic) → pypdf fallback | ✅ | ✅ (native) |
| DOCX | python-docx | ✅ (Heading 1/2/3 styles) | Logical (2000-char splits) |
| MD | built-in | ✅ (ATX `#`/`##`/`###`) | Logical splits |
| TXT | built-in | — | Logical splits |

**Scanned PDF detection**: raises `ParseError` if PDF has 0 pages or < 20 chars/page — marked `failed` with clear user-facing message. No OCR.

### 4. Chunking
- Target: **400–600 tokens** (tiktoken `cl100k_base`; falls back to char/4)
- Overlap: **12%** (~50–72 tokens at target max)
- **Code fences never split** — triple-backtick/tilde blocks collected atomically
- Heading path carried into every chunk as `heading_path: list[str]`

### 5. Embeddings — interface with 3 backends
| Backend | Env value | Notes |
|---------|-----------|-------|
| BGE-M3 | `EMBEDDING_BACKEND=bge_m3` | Lazy load; auto device (CUDA/MPS/CPU) |
| Hosted API | `EMBEDDING_BACKEND=api` | OpenAI-compatible `/v1/embeddings` |
| Mock | `EMBEDDING_BACKEND=mock` (default) | Deterministic hash-based; no ML deps; tests |

**Model+dimension recorded per collection**. Mixing refused:
> `RuntimeError: Dimension mismatch for collection 'bookey_python_mock': existing=384, requested=1536`

### 6. Vector Store — interface with 2 backends
| Backend | Env value | Distance | Notes |
|---------|-----------|----------|-------|
| ChromaDB | `VECTOR_STORE=chroma` (default) | Cosine (`hnsw:space=cosine`) | Ephemeral (tests) or persistent (dev) |
| pgvector | `VECTOR_STORE=pgvector` | — | Stub; requires PostgreSQL |

Collections are namespaced: `bookey_{course_id}_{embedding_model}`.

### 7. Retrieval
Pipeline: `embed query → ANN search → keyword boost → MMR → score threshold → context cap`

- **Course isolation**: each collection is namespaced by course — cross-course queries return nothing
- **Access control**: `allowed_document_ids` parameter filters results before ranking
- **MMR** (λ=0.7): Jaccard-based diversity reduces duplicate passages
- **Score threshold**: configurable (default 0.0 for production embeddings)
- **Provenance**: every `RetrievedPassage` carries `chunk_id`, `document_id`, `page_number`, `heading_path`, `course_id`

### 8. Prompt-injection defense (in depth)

> **Primary**: Retrieved text is wrapped in hard delimiters — never mixed with instructions:
> ```
> === RETRIEVED DOCUMENT PASSAGE [1] ===
> {text}
> === END PASSAGE [1] ===
> ```
> The system prompt (B3) must declare everything between delimiters as *untrusted data*, not instructions.

Additional layers:
- Per-chunk cap: `MAX_CHUNK_CHARS = 4000`
- Total context cap: `MAX_CONTEXT_CHARS = 12000`
- Provenance metadata kept separate from passage text

Tests confirm documents containing:
- `"ignore all instructions"` → returned as DATA inside delimiters, not executed
- `"reveal system prompt"` → same; delimiter makes the boundary clear
- Obedience-seeking text → retrieval layer only returns; LLM obedience is a B3 concern

### 9. Delete cascade
`DELETE /api/admin/documents/{doc_id}`:
1. Storage file deleted
2. Vector store chunks deleted (`delete_by_document`)
3. DB record deleted → cascades to `document_chunks` via FK

### 10. Retry
`POST /api/admin/documents/{doc_id}/retry` on `status="failed"`:
- Resets status to `"uploaded"`
- Background re-processing deletes old chunks + vectors before re-inserting
